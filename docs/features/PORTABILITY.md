# نقل البيانات — التصدير/الاستيراد (PDPL R-1)

نظام تصدير/استيراد كامل داخل التطبيق يُغلق فجوة PDPL **R-1** (حقّ نقل البيانات) ببرمجيات
عاملة. محلّي بالكامل — **صفر شبكة، صفر Supabase**.

> **ملاحظة انحراف (موثّقة):** المهمّة أشارت إلى `docs/DATA-EXPORT-DESIGN.md` كمصدر تصميم،
> لكن الملفّ **غير موجود في `origin/integration/wave4`**. نُفِّذ النظام وفق متطلّبات المهمّة
> التفصيلية + أنماط الشيفرة القائمة (نمط المسح fail-safe في `accountScope`، نمط لقطة
> المزامنة)، وهذا المستند هو مرجع التصميم البديل.

## أين
- المنطق: `src/lib/portability/**` (جديد) — `registry` · `format` · `exporter` · `importer` · `index`.
- الواجهة: قسم **«بياناتي»** في `src/views/ProfileV2.tsx` (إعدادات v2 ← بياناتي، وأيضًا من شاشة الخصوصية).
- الإثبات: `scripts/portability-proof.ts` + `scripts/run-portability-proof.mjs` (= `test:portability`).

## التعداد (fail-safe مثل المسح)
«مساحة المستخدم» تُعرَّف كنمط المسح في `accountScope.wipeUserData`: كل مفاتيح `qimmah:*`
عدا قائمة استثناء صريحة. لذا **أي متجر جديد يُصدَّر افتراضيًا** ولا يُنسى بصمت:
- `STORE_DEFS` يعرّف المتاجر المعروفة (٢٢) بمُحمِّلها الحقيقي + شكلها + عدّها.
- `sweepUnregistered` يلتقط أي مفتاح `qimmah:*` جديد غير مسجّل وغير مستثنى (بقايا).
- **المستثنى صراحةً:** قائمة السماح العامّة في `accountScope` (تفضيلات جهاز/كاش/**رمز الجلسة**)،
  سباكة المزامنة (`syncQueue/syncBackup/sync:meta`)، أعلام الاختبار، نسخ المفاتيح القديمة المكرّرة.

## إعادة الترميز (لماذا حقن الحساب مستحيل)
لا يحمل أي متجر معرّف المالك **داخل قيمته** — الهوية في المفتاح فقط:
- لاحقة مفتاح: `qimmah:todo:v1:<uid>`, `qimmah:activeSession:v1:<uid>`.
- مفتاح خريطة: `qimmah:customPlan:v1` = `Record<uid, …>`.

عند الاستيراد تُكتب المتاجر المربوطة بالمالك تحت **المستخدم الحالي حصراً** (`keyFor(uid)` /
`map[ownerToken(uid)]`). فاستيراد نسخة المستخدم A بواسطة B يهبط تحت B — **حقن بيانات في حساب
آخر مستحيل بنيويًّا** (لا مكان لكتابة مفتاح مالك آخر).

## خطّ الاستيراد (صارم، ذرّي)
1. **قبل أي كتابة:** حجم الملفّ (≤٢٥MB) → `JSON.parse` عبر reviver يرفض `__proto__`/`constructor`/`prototype`
   → النوع `qimmah-data-export` → **بوّابة `schemaVersion`** → تحقّق شكل كل متجر + سقوف (`reject-on-any-invalid`
   برسالة عربية **تسمّي المتجر الفاشل**). متجر مجهول أو مفتاح مستثنى في البقايا → رفض.
2. **معاينة:** عدّ لكل متجر («تمارين: ٨٤ · مهام: ٣ …») + تاريخ النسخة + تأكيد صريح.
3. **تطبيق ذرّي:** لقطة تراجع لكل مفتاح سيُمسّ → كتابة معاد الترميز → **تحقّق نهائي بالمُحمِّلات
   الحقيقية**؛ أي رمي → استرجاع اللقطة كاملةً + مسحها + خطأ يسمّي المتجر.
4. **تراجع بلمسة:** `undoImport` يُعيد ما قبل الاستيراد تمامًا. لقطة التراجع (`qimmah:portability:undoBackup:v1`)
   `qimmah:*` → يمسحها `wipeUserData` تلقائيًّا عند تبديل الحساب/تسجيل الخروج، وتُستثنى من التصدير.

## التسليم (محلّي بحت)
- **التصدير:** يُفضّل ورقة المشاركة الأصلية عبر **Web Share API** (ملفّ) — تعمل داخل WKWebView
  على iOS ١٥+ — وإلا **تنزيل Blob** على الويب. لا `fetch`/`XHR` إطلاقًا.
- **الاستيراد:** منتقي ملفّات `<input type=file accept=.json>` + `FileReader`.
- **قيد بيئي موثّق:** `@capacitor/filesystem` و`@capacitor/share` **غير مثبّتَين**، و`package.json`
  خارج نطاق هذا الفرع. لذا اعتمد النظام مسار الويب المعياري (Share API + تنزيل) الذي يوفّر
  ورقة مشاركة أصلية دون إضافة اعتمادية. **متابعة لقائد wave4:** إضافة `@capacitor/filesystem`+`share`
  لحفظ مباشر في «الملفّات» على iOS.

## نموذج التهديد (STRIDE) — الملفّ المستورَد = مُدخل غير موثوق
| التهديد | المتّجه | الضابط |
|---|---|---|
| **Elevation** | استيراد يكتب رمز الجلسة `qimmah:supabase-auth:v1` → اختطاف | يُرفض في التحقّق (مستثنى) ولا يوجد كـ id متجر؛ حارس `isExcludedKey` مكرّر عند التطبيق. **مُثبَت:** رمز الجلسة لم يُكتب إطلاقًا. |
| **Tampering** | حقن بيانات حساب A في حساب B | إعادة ترميز للمستخدم الحالي حصراً — لا مفتاح مالك آخر يُكتب. |
| **Injection** | تلويث النموذج (`__proto__`) | reviver يرفض المفاتيح الخطيرة في أي عمق. |
| **DoS** | ملفّ ضخم/متضخّم | سقف ٢٥MB + سقف ١٠٠٬٠٠٠ عنصر/متجر. |
| **Spoofing** | استيراد أثناء جلسة استعادة كلمة المرور | `applyImport` يُرفض حين `recoveryActive`؛ الواجهة تُعطّل الزرّ. |
| **Integrity** | استبدال جزئي عند فشل | تطبيق ذرّي: لقطة → كتابة → تحقّق بالمُحمِّلات → استرجاع عند الفشل + تراجع بلمسة. |
| **Info Disclosure** | تسريب عبر الشبكة | التصدير محلّي بالتصميم (Share API/Blob) — لا استدعاء خادم. |

## الاختبار (`test:portability` — ٣٥ فحصًا خضراء)
جولة كاملة أمينة (export→wipe→import→deep-equal عبر المُحمِّلات) · بوّابة الإصدار · رفض
مشوّه/معادٍ لكل شكل متجر + تلويث النموذج + النوع + الحجم + المفتاح المستثنى · إعادة الترميز
(A→B) بلا حقن · التراجع يُعيد تمامًا · عزل مستخدمَين · رفض أثناء الاستعادة.
التشغيل: `node scripts/run-portability-proof.mjs`.

تحقّق زمن التشغيل (واجهة فعلية): معاينة العدّ، تطبيق معاد الترميز إلى `guest` فقط، رمز الجلسة
سليم، لقطة التراجع تلتقط ما قبل الاستيراد، ومسار الخطأ يسمّي المتجر — بالصور.

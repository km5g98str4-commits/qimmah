# Q18 — «صحتي من Apple»: لقطات إثبات

اللقطات مولَّدة آليًا بـ `node scripts/health-link-shots.mjs` بأبعاد iPhone 15
(393×852pt @2x)، عربي وإنجليزي، للحالات الأربع.

الحالات الثلاث المتاحة تحتاج منصّة iOS أصلية (`isHealthReadPlatform()`)، فالسكربت
يحقن `CapacitorCustomPlatform` — نقطة الحقن الرسمية في Capacitor — ويزرع أعلام
الاتصال في `localStorage`. **لا يلمس مصدر التطبيق**، والقيمة الوحيدة المزروعة عيّنة
خطوات صورية واحدة لإظهار حالة «مربوط».

| ملف | الحالة |
|---|---|
| `card-not-connected-{ar,en}.png` | غير مربوط — الزرّ «اربط صحتي» |
| `card-needs-review-{ar,en}.png` | يحتاج مراجعة — اكتمل الطلب ولا بيانات |
| `card-connected-{ar,en}.png` | مربوط — وصلت بيانات فعلًا |
| `card-unavailable-{ar,en}.png` | غير متاح على هذا الجهاز — بلا زرّ |
| `page-*-{ar,en}.png` | صفحة الربط لكل حالة متاحة (لقطة كاملة) |

## مسار المستخدم بعد الإصلاح

1. **الإعدادات** ← أول بطاقة في الشاشة: «صحتي من Apple» مع الحالة الحالية.
2. **غير مربوط** ← زرّ واحد «اربط صحتي».
3. الضغط يُطلق **طلبًا مجمّعًا واحدًا** لكل الأنواع المدعومة على الجهاز
   (`requestAllHealthAccess`) — ورقة صحة واحدة من iOS، لا ورقة لكل مقياس.
4. بعد اكتمال الورقة تُسحب أول دفعة فورًا (`syncAllEnabled`، قراءة صرفة) ثم يفتح
   التطبيق **صفحة الربط**.
5. الصفحة تعرض: الحالة · تنويه «قراءة فقط» · **خطوات تعديل الصلاحيات من تطبيق
   صحتي** · قائمة الأنواع المدعومة وحالة كلٍّ منها.
6. لاحقًا تعرض البطاقة «مربوط» أو «يحتاج مراجعة»، وزرّها يصير «إدارة الربط»
   ويفتح الصفحة نفسها.

## قاعدة الصدق

iOS **لا يكشف** رفض صلاحية القراءة: `requestAuthorization` ينجح سواء وافق المستخدم
أو رفض، و`authorizationStatus` للقراءة يُرجع `notDetermined` عمدًا حمايةً للخصوصية.
لذلك لا توجد حالة «مرفوض» في أي مكان — بعد الطلب وبلا بيانات نقول «يحتاج مراجعة»
ونشرح كيف يراجعها المستخدم بنفسه. الإثبات `npm run test:health-link` يمنع تسرّب
كلمة «مرفوض/denied» إلى أي نص باللغتين.

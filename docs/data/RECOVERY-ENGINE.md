# محرّك التعافي v2 (P11) — `claude/recovery-engine-v1`

محرّك قواعد مُرقَّم الإصدار (`RULES_VERSION = v2.0.0`) في `src/lib/recoveryEngine.ts`
يحوّل مؤشرات راحة وحمل تدريبي — كلها اختيارية — إلى **اقتراح استشاري بأثر قرار كامل**.
ليس طبيًا، ولا يعدّل الخطة أبدًا.

## القرارات الحاكمة

| القرار | التفصيل |
|---|---|
| قاعدة D — لا تعديل خطة | المحرّك يُخرج اقتراحًا فقط؛ الموافقة/الرفض عقد واجهة خارج الوحدة. لا استيراد لأي متجر خطة (حارس نصّي في البرهان)، وكتابة واحدة فقط: سجلّ المحرّك نفسه. |
| كل المدخلات اختيارية | يعمل يدويًا بالكامل بلا HealthKit وبلا سجلّ تدريب. الغائب يخفض الثقة ولا تُخترع قيمة أبدًا. |
| مضاد المبالغة | قراءة سيئة واحدة لا تنتج «راحة»: الراحة تتطلّب **عاملين مُجهِدين فأكثر بهامش واضح (≥5)** — أو ألمًا عضليًا **شديدًا** صريحًا، وهو العامل الوحيد الحاسم منفردًا (حماية المستخدم). |
| التعارض ⇒ حذر | إجهاد واستشفاء بفارق ضئيل ⇒ `proceed` بعلم `conflicting` وثقة مسقوفة ≤0.35 — لا حسم مُخترع. |
| صدق الثقة | `confidence = 0.2 + 0.7 × (العوامل الحاضرة / 8)` ثم سقف التعارض/قلة البيانات. لا تُرفع اصطناعيًا. |
| لا لغة تشخيصية | مؤشرات راحة وحمل فقط («نوم سيّئ مُبلَّغ»، «حمل تدريبي مرتفع») — حارس نصّي في البرهان يمنع مفردات التشخيص/العلاج. |
| نصوص ثنائية | كل ملاحظة عامل `{ ar, en }` — البرهان يتحقق من امتلاء اللغتين. |

## المدخلات (كلها اختيارية)

- **تقرير ذاتي**: جودة النوم (`poor/ok/good`) · مدة النوم بالساعات · الطاقة · التوتّر.
- **ألم عضلي لكل منطقة**: `chest/back/shoulders/arms/legs/core/general` × `none/mild/moderate/severe`.
- **حمل تدريبي**: `deriveTrainingLoad()` من جلسات `historyStore` — آخر ٧ أيام مقابل الأسبوع السابق (٨–١٤ يومًا)، بالنسبة بين الأطقم المكتملة (أو الجلسات للسجلّات القديمة). أسبوعان فارغان ⇒ `undefined`.
- **إشارات P9** (اختيارية تمامًا): نبض الراحة + HRV عبر `healthSignalsFromStore()` — قيمة حديثة (اليوم/الأمس) مقابل خط أساس ≥3 أيام من متجر عيّنات P9. بيانات غير كافية ⇒ لا إشارة، والمحرّك يعمل يدويًا.

## المخرجات — `RecoveryEvaluation`

```
{ suggestion: proceed | reduce_volume | reduce_intensity | rest,
  confidence: 0–1, score: 0–100,
  reasons: [{ factor, direction, weight, note:{ar,en}, decisive? }],
  flags: { conflicting, lowData, decisiveSoreness },
  rulesVersion: 'v2.0.0' }
```

`reasons` هو أثر القرار الكامل: كل عامل حاضر يُذكر باتجاهه (`recovered/strained/neutral`)
ووزنه (0–3). الحمل المرتفع يوجّه نحو `reduce_volume`؛ الإجهاد العام نحو `reduce_intensity`.

## السجلّ والاتجاه

- **سجلّ v2**: `qimmah:recovery-log:v2:<owner>` (مسجَّل في `userDataKeys.ts`)، سقفه 180 كسياسة v1، فحص اليوم يستبدل فحص اليوم نفسه، كل إدخال مختوم بـ`rulesVersion`.
- **اتجاه أسبوعي**: `recoveryTrend(owner, 7|28)` — سلسلة يومية بأيام فارغة صريحة (`null`)، واتجاه `improving/declining/stable` بمقارنة نصفي الفحوص الفعلية؛ أقل من فحصين ⇒ `stable` بصدق.

## الوحدة القديمة (v1)

`src/lib/recovery.ts` **تبقى تعمل** (deprecated بتعليق فقط): `RecoveryView.tsx` ما زالت
عليها، و`test:recovery` يبقى أخضر. سجلّ v1 يُستورد للقراءة عبر
`ensureRecoveryEngineMigrated(owner)` (خلال `runMigration` الموحّد): idempotent،
بلا حذف لـ v1، الإدخالات المستوردة موسومة `rulesVersion: 'v1-import'` بثقة 0.3،
وإدخال v2 الموجود يفوز لنفس اليوم.

- لا واجهة مستخدم في هذه الموجة (الشاشات خارج نطاق P11 المحظور: `src/views/*`) — الربط بشاشات التعافي قرار موجة لاحقة.

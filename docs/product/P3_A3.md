## TASK 1 — Vendor images locally (resilience fix) ✅

**Problem.** The 136 matched exercise images were **hotlinked** to
`raw.githubusercontent.com/yuhonas/free-exercise-db` — every card render depended on that host being
reachable. If GitHub raw was blocked/slow/down, users saw placeholders instead of real images.

**Change.**
- `scripts/build-exercise-media.mjs` now **downloads** each matched frame into
  `public/exercise-images/<exerciseId>/0.jpg` (and `1.jpg` when the source has a distinct end frame)
  at build time. Download is **idempotent** (skips files already on disk; `FORCE_REDOWNLOAD=1` to refresh).
- `src/data/exerciseMedia.ts` (generated) now emits **local** primary paths + **remote fallback**:
  ```ts
  "barbell-bench-press": {
    "img0": "/exercise-images/barbell-bench-press/0.jpg",
    "img1": "/exercise-images/barbell-bench-press/1.jpg",
    "img0Remote": "https://raw.githubusercontent.com/.../0.jpg",  // fallback only
    "img1Remote": "https://raw.githubusercontent.com/.../1.jpg"
  }
  ```
- `src/components/ExerciseMedia.tsx` now walks a fallback chain **local → remote → clean placeholder**
  (via a small `FallbackImg` that advances through sources on `onError`). Animated GIF, when present,
  now falls back to the static frames instead of jumping straight to the placeholder.
- License: `free-exercise-db` is **Unlicense / public domain** → committing the images is fine.

**Proof (runtime + filesystem):**
- `find public/exercise-images -name '*.jpg' | wc -l` → **272** (136 exercises × 2 frames).
- `npm run proof:media` → *“136/136 تمرينًا له إطارَان محليّان موجودان + fallback بعيد.”*
  (every media entry’s `img0`/`img1` is a `/exercise-images/…` path, the file **exists on disk**,
  and a `raw.githubusercontent` fallback is present.)
- `npm run build` → `dist/exercise-images` contains **272** jpgs; the built JS references the local
  paths as primary. **The app no longer needs the remote host to render exercise images.**

## TASK 2 — Home-gym media (no machine photos) ✅

The home plan’s equipment filter (`planGenerator.ts`, `access==='home'`) only allows
`dumbbell / barbell / bodyweight / band / bench` — so `machine`/`cable` exercises **structurally cannot**
enter a home plan. The remaining risk was a *home-eligible* exercise being **matched to a machine/cable
photo** by the media builder.

- Found & fixed one: `rear-delt-fly` (dumbbell) was matching `Cable_Rear_Delt_Fly`. Added a
  `MANUAL_OVERRIDE → Reverse_Flyes` (dumbbell) and refreshed the local frames.

**Proof:** `npm run proof:media` →
*“98 تمرينًا مؤهَّلًا منزليًا: 77 بصورة منزلية مناسبة، 21 ببديل نظيف — **0 صورة جهاز**.”*
(the proof scans every home-eligible exercise: each resolves to a home-appropriate image **or** a clean
placeholder; none maps to a machine/cable source and none carries machine/cable equipment.)

## Risks / notes

- **+18 MB** in the repo (272 jpgs, avg ~65 KB). Acceptable for a self-contained, offline-resilient
  template; the alternative (hotlinking) is the fragility we set out to fix.
- Changing a `MANUAL_OVERRIDE` requires `FORCE_REDOWNLOAD=1 npm run build:media` (or deleting that
  exercise’s folder) so the stale local frame is replaced — the map’s remote URL updates either way,
  but the committed jpg would otherwise lag.
- 34 exercises (cardio/mobility) remain intentionally image-less → clean placeholder + working
  YouTube-search link. Coverage stays 136/170 (80%).

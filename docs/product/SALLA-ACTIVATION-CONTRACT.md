# Salla → Premium — عقد التكامل

**الموجة:** `[CTO-BACKEND-001]` ثم `[CTO-86]` · **الفرع:** `claude/salla-activation` · **الأساس:** `df85c77`
**النطاق:** خادم فقط. لا واجهة ولا بوّابة مسارات ولا شاشة Premium — تلك موجات لاحقة.

> **هذا الملف عقدٌ لا شرح.** ما يبنيه العميل (iOS/Web) لاحقًا يستهلك ما هنا حرفيًا.

## 0. عقد أحداث سلة — منقول من المصدر الرسمي

**المصدر:** `SallaApp/salla-partners-agent-kit` →
`.agents/skills/salla-app-functions-design/references/event-contexts.md` ·
`SallaApp/webhook-actions-js/README.md` · [docs.salla.dev/doc-421119](https://docs.salla.dev/doc-421119)

| البند | القيمة | الحالة |
|---|---|---|
| حدث الطلب المدفوع | `order.status.updated` | ✅ موثَّق |
| `order.payment.updated` | **«تغيّرت وسيلة الدفع»** — ليس حدث دفع | ✅ موثَّق (README سلة حرفيًا) |
| معرّف الطلب | `data.order.id` (المتداخل) · `data.id` (المسطّح) | ✅ موثَّق |
| بريد المشتري | `…order.customer.email` | ✅ موثَّق |
| المبلغ · العملة | `…order.amounts.total.{amount,currency}` | ✅ موثَّق |
| المنتج | `…order.items[].product.id` · `items[].sku` | ✅ موثَّق |
| ترويسات التوقيع | `X-Salla-Security-Strategy` · `X-Salla-Signature` | ✅ موثَّق |
| الإعادة | ٣ محاولات · ~٥ دقائق | ✅ موثَّق |
| الطابع الزمني | `created_at` (مظروف) | ✅ موثَّق |
| **أي شريحة تعني «وصل المال»** | `payment_pending` · `under_review` · `in_progress` · `completed` مسرودة **بلا تصريح أيّها يضمن الدفع** | ⚠️ **UNKNOWN** |
| **معرّف حدث فريد من سلة** | لا ترويسة ولا حقل موثَّق | ⚠️ **UNKNOWN** — نستعيض ببصمة sha256 للجسم |
| **دلالة `is_pending_payment`** | الحقل موجود في الحمولة الرسمية، وسلوكه غير موصوف نصًّا | ⚠️ **UNKNOWN جزئيًا** — يُستعمل حاجزًا فقط حين يكون `true` |
| **استراتيجية الرمز** | التوثيق يقول `Authorization`؛ تنفيذات طرف ثالث تقول `X-Salla-Signature` | ⚠️ **UNKNOWN** — الافتراضي `signature` وحده المعتمد |

### شكلا الحمولة — والفخّ بينهما

```jsonc
// order.status.updated — الطلب **متداخل**
{ "event": "order.status.updated", "merchant": …, "created_at": …,
  "data": {
    "id": 198290473,        // ← معرّف تغيّر الحالة. **ليس** معرّف الطلب.
    "status": "تم التنفيذ",  // ← نصّ معروض. **ليس** كائنًا فيه slug.
    "order": { "id": 629263027, "status": { "slug": "completed" },
               "amounts": {…}, "customer": {…}, "items": [...],
               "is_pending_payment": false }
  } }
```

> **قراءة `data.id` معرّفًا للطلب تفسد المفتاح.** معرّف تغيّر الحالة يتبدّل مع كل
> انتقال، فيصير الطلب الواحد «طلبات» كثيرة: التكرار لا يُلتقط، وحارس ربط الهوية
> لا يجد الطلب السابق فلا يشتغل. الطلب يُقرأ من `data.order` حصرًا.

## 1. الدورة كاملة

```
شراء في سلة
   └─► webhook موقَّع  ──►  supabase/functions/salla-webhook
                              ① تحقّق HMAC        (قبل أي كتابة)
                              ② تحليل الحمولة
                              ③ قرار المنحة       (سياسة صريحة، فشل مغلق)
                              ④ salla_ingest_event (معاملة واحدة)
                                   ├─ salla_webhook_events  ← تدقيق
                                   ├─ purchase_ledger       ← سجلّ دائم
                                   └─ entitlements          ← المنحة
                                          │
   تسجيل لاحق بنفس البريد ──► claim_pending_grants() ──┘
```

## 2. ما يستهلكه العميل — ثلاث دوال لا رابع

| الدالة | الدور | من ينادي |
|---|---|---|
| `my_entitlement()` | **القراءة الوحيدة المعتمدة.** الحالة تُشتقّ من وقت القاعدة، لا من عمود مخزَّن. | `authenticated` |
| `claim_pending_grants()` | بعد **كل** تسجيل/تأكيد بريد. يلتقط شراءً سبق الحساب. | `authenticated` |
| `redeem_access_code(code)` | استرداد كود وصول. | `authenticated` |

### `my_entitlement()` — الشكل المُعاد

```
state            text   ← الحقل الوحيد الذي تبني عليه الواجهة
entitlement_type text
source           text
activated_at     timestamptz
expires_at       timestamptz
no_expiry        boolean
updated_at       timestamptz
```

**قيم `state` — سبع لا ثامن لها:**

| القيمة | معناها للواجهة |
|---|---|
| `premiumActive` | وصول كامل، بلا انتهاء |
| `specialAccessActive` | وصول بكود، موقوت |
| `trialActive` | تجربة جارية |
| `trialExpired` | التجربة انتهت |
| `revoked` | **محظور** — لا يُرفع بأي مسار خدمة ذاتية |
| `noAccess` | لا منحة |

> ⚠️ **لا تحسب الانتهاء في العميل.** `expires_at` للعرض فقط؛ ساعة الجهاز
> قابلة للتقديم، وساعة القاعدة لا. القرار دائمًا `state`.

> ⚠️ **`revoked` ليست خطأً يُعاد المحاولة عليه.** لا تُخفِها ولا تُترجمها
> «حدث خطأ». نصّها للمستخدم يُحسم في موجة النصوص، لا هنا.

### متى تُنادى `claim_pending_grants()`

**بعد تسجيل الدخول وبعد تأكيد البريد — في الحالتين.** المشتري قد يكون دفع
قبل أن يملك حسابًا أصلًا؛ السجلّ ينتظره في `purchase_ledger`، وهذه الدالة هي
ما يحوّله إلى منحة. تُرجع نفس قيم `state` أعلاه.

وهي **آمنة للتكرار**: نداؤها بلا شراء معلَّق يعيد الحالة القائمة ولا يغيّر شيئًا.

### الأخطاء التي يتعامل معها Web/iOS

الدوال ترفع استثناءات Postgres؛ يصل العميل `error.message` عبر supabase-js.
**طابِق على المُعرِّف النصّي** لا على نصّ الرسالة كاملًا ولا على `code`.

| المُعرِّف | متى | ما يفعله العميل |
|---|---|---|
| `not authenticated` | جلسة غائبة/منتهية | أعد التوجيه لتسجيل الدخول |
| `email_not_verified` | البريد غير مؤكَّد | اعرض شاشة تأكيد البريد |
| `access_revoked` | الهوية محظورة | **لا تُعِد المحاولة** — رسالة نهائية ومسار دعم |
| `invalid_code` | كود غير موجود/معطَّل/منتهٍ | «الكود غير صالح» — نصّ واحد لكل الحالات عمدًا (لا يُكشف أي سبب) |
| `code_already_redeemed` | الكود استُهلك | «سبق استخدام هذا الكود» |
| `trial_already_used` | التجربة استُهلكت لهذه الهوية | «سبق أن استخدمت التجربة» |
| `trial_not_applicable` | حالة أعلى قائمة (Premium مثلًا) | لا تعرض زرّ التجربة أصلًا |

> ⚠️ **`invalid_code` نصٌّ واحد عمدًا.** التمييز بين «غير موجود» و«منتهٍ» و«معطَّل»
> يحوّل الرسالة إلى مُخبِر يعدّ للمهاجم الأكواد الصحيحة — وتحديد المعدّل ما زال
> عائقًا خارجيًا (§7)، فالغموض هنا حماية لا كسل.

> **`purchase_identity_conflict` لا يصل العميل إطلاقًا** — مسار الخادم وحده.
> إن ظهر في سجلّ العميل يومًا فهو خطأ تسريب مسار، لا حالة يعالجها.

## 3. ما **لا** يفعله العميل — أبدًا

| ممنوع | لماذا |
|---|---|
| كتابة أي صفّ في `entitlements` | لا سياسة كتابة على الجدول أصلًا؛ كل تغيير عبر دالة `SECURITY DEFINER` |
| نداء `admin_grant_premium` أو `salla_ingest_event` | `service_role` حصرًا — يُثبِته `test:salla-webhook` لكل من `anon` و`authenticated` |
| تخزين «هو Premium» محليًا كمصدر حقيقة | كذبة بمجرّد انتهاء المدّة أو الحظر. خزّنه **ذاكرةً مؤقّتة** واقرأ `my_entitlement()` عند كل إقلاع |
| منح وصول من ردّ المتصفّح بعد الدفع | صفحة الشكر ليست إثبات دفع. الإثبات هو الـwebhook وحده |
| توليد كلمة مرور أو إرسالها | ممنوع بالميثاق §0.1. التفعيل يمرّ برابط دعوة أو كلمة مرور يضعها المستخدم |

## 4. متغيّرات البيئة — تُضبط بلوحة Supabase، لا في المستودع

| المتغيّر | إلزامي | ملاحظة |
|---|:--:|---|
| `SUPABASE_URL` · `SUPABASE_SERVICE_ROLE_KEY` | ✅ | تحقنهما المنصّة |
| `SALLA_WEBHOOK_SECRET` | ✅ | استراتيجية التوقيع (الافتراضية لدى سلة) |
| `SALLA_WEBHOOK_TOKEN` | ⬜ | فقط إن استُخدمت استراتيجية الرمز |
| `SALLA_AMOUNT_POLICY` | ✅ | `exact` أو `off` — **الغياب يوقف الطرفية عمدًا** |
| `SALLA_EXPECTED_AMOUNT_MINOR` | ✅ مع `exact` | بأصغر وحدة: `1999` = ١٩٫٩٩ ريالًا |
| `SALLA_PAID_STATUS_SLUGS` | ✅ | **بلا افتراضي** — يُضبط بعد مطابقة حمولة حقيقية (§0) |
| `SALLA_EXPECTED_PRODUCT_IDS` | ✅ | **بلا افتراضي** — هوية منتج Premium المعتمدة |
| `SALLA_EXPECTED_CURRENCY` | ⬜ | افتراض `SAR` |

> **ثلاثة متغيّرات بلا افتراضي، والغياب يوقف الطرفية (`500`) لا يتساهل.**
> أخطر ما تفعله بوابة دفع أن تمنح لأن متغيّرًا لم يُضبط:
> - **المبلغ** — بلا سياسة معلَنة يصير أي مبلغ مقبولًا.
> - **الشريحة** — سلة لا توثّق أيّها يعني «وصل المال»، فالقيمة قرار يُعلَن لا يُورَّث.
> - **المنتج** — «أي طلب ناجح في سلة» ليس سند صلاحية لـPremium؛ المتجر يبيع غيرها.

### هوية منتج Premium — ما يُقبل سندًا وما لا يُقبل

| يُقبل | لا يُقبل |
|---|---|
| `items[].product.id` (المعرّف المستقرّ) | **الاسم المعروض** — يغيّره التاجر من اللوحة |
| `items[].sku` (يعتمده التاجر) | **سعر يرسله العميل** |
| | **رابط إعادة توجيه** أو صفحة شكر |
| | **أي طلب ناجح** في المتجر |

## 5. عقد الردّ — ولماذا الرفض الدائم `200`

سلة **تعيد الإرسال ثلاث مرّات بفواصل ~٥ دقائق** على أي ردّ غير ناجح.

| الحالة | HTTP | السبب |
|---|:--:|---|
| `processed` · `duplicate` · `ignored` · `rejected` | `200` | قرارات **نهائية** — الإعادة لا تغيّرها وتلوّث التدقيق |
| توقيع فاسد/غائب | `401` | طلب لا نعترف به |
| حمولة مشوَّهة | `400` | لا تُصلحها إعادة |
| سوء تهيئة · عطل قاعدة | `500` | **يُراد** أن تُعيد سلة — قد تنجح |

تصنيفات سطر التدقيق: `received` · `verified` · `ignored` · `processed` ·
`duplicate` · `rejected` · `failed`.

**والتمييز بين `ignored` و`rejected` تشغيليّ لا شكليّ:**
`ignored` = ليس لنا أو لم يُدفع بعد. `rejected` = طلب **مدفوع** يخالف السياسة
— يستحق عين إنسان، لا أن يغرق بين آلاف المتجاهَل.

## 6. الثوابت التي يقوم عليها كل ما سبق

1. **`(provider, provider_order_id)` هوية شراء واحدة.** نفس الهوية ⇒ idempotent.
   هوية مختلفة ⇒ `purchase_identity_conflict`، **فشل مغلق**. والمقارنة عبر كل
   إصدارات الملح كي لا يصير دورانه بابًا خلفيًا.
2. **الإلغاء الدائم يعلو على الشراء.** يُسجَّل الشراء (المال حقيقي فأثره يُحفَظ)
   وتُحجب المنحة. `admin_unrevoke` وحده يرفع.
3. **السجلّات الدائمة بلا `user_id`** — تنجو من `delete_own_account()`. وهذا ما
   يجعل «اشتريت» تبقى صحيحة بعد حذف الحساب، و«مرّة واحدة» تعني مرّة واحدة.
4. **لا بريد صريح في أي سجلّ دائم** — بصمة مُملَّحة بإصدار مُرقَّم.
5. **الحالة تُشتقّ ولا تُخزَّن** — لا عمود `status`.

## 7. ما يبقى قبل التفعيل الحقيقي — عوائق مسمّاة

**العوائق القاطعة (تمنع حتى التحقّق على staging):**

| العائق | الحالة | بيد من |
|---|---|---|
| **مشروع Supabase تجريبي** | ❌ **غير موجود** — لا `.env` في المستودع، ولا `supabase/config.toml`، ولا CLI مثبَّت، ولا رمز دخول | **المؤسس** |
| **بيئة/آلية اختبار في سلة** | ❌ **غير متاحة** — لا حساب ولا متجر تجريبي ولا أسرار | **المؤسس** |
| تطبيق الهجرات على قاعدة حيّة | ⏳ لم يحدث | **المؤسس** — الميثاق §1 |
| نشر الطرفية | ⏳ لم يحدث | **المؤسس** |

**عوائق المعرفة (تُحسم بحمولة حقيقية، لا باجتهاد):**

| العائق | لماذا |
|---|---|
| **`SALLA_PAID_STATUS_SLUGS`** | التوثيق يسرد الشرائح ولا يصرّح أيّها يضمن وصول المال — §0 |
| **دلالة `is_pending_payment`** | الحقل في الحمولة الرسمية وسلوكه غير موصوف؛ يُستعمل حاجزًا حين `true` فقط |
| **استراتيجية الرمز** | تعارض بين التوثيق (`Authorization`) وتنفيذات طرف ثالث (`X-Salla-Signature`) |
| **معرّف حدث فريد** | لا ترويسة موثَّقة؛ نستعيض ببصمة الجسم — كافية للإعادة، غير كافية لو أعادت سلة الجسم نفسه بمعنى مختلف |

**عوائق مؤجَّلة:** تحديد المعدّل (عائق بنية خارجي، §11.2) · P3–P7 (الإعداد · المزوّد ·
بوّابة المسارات · الشاشة · أدوات الإدارة).

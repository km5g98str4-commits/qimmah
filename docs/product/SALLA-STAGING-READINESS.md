## 1. ما تحتاج تجهيزه — Supabase

أنشئ مشروعًا **جديدًا مستقلًّا** (لا تعيد استخدام الإنتاج ولا فرعًا منه).

| المطلوب | من أين | أين يُخزَّن |
|---|---|---|
| **Project ref** (مثل `abcdefghijklmnop`) | من رابط المشروع | ✅ **يُكتب في المستودع** — `scripts/staging/environment.json` → `stagingAllowedRefs` |
| **Project ref للإنتاج** | رابط مشروع الإنتاج الحالي | ✅ **يُكتب في المستودع** — نفس الملف → `productionRefs` |
| Project URL | لوحة Supabase → Settings → API | متغيّر بيئة محلّي `SUPABASE_URL` (لا يدخل Git) |
| `anon` key | نفس الصفحة | متغيّر بيئة محلّي — **لا يدخل Git** |
| `service_role` key | نفس الصفحة | 🔐 **لوحة Supabase حصرًا** كسرّ للطرفية — لا ملف ولا Git ولا محادثة |
| كلمة مرور قاعدة البيانات | Settings → Database | 🔐 مدير كلمات المرور — تُستعمل لحظيًا عند `db push` |
| رمز دخول Supabase CLI | `supabase login` (تفاعليًا) | 🔐 يخزّنه CLI في `~/.supabase` — لا تنسخه |

> **المراجع ليست أسرارًا.** `project ref` معرّف عام يظهر في كل رابط API، وكتابته في
> المستودع هي ما يجعل حارس البيئة (§4) حتميًا. **المفاتيح** وحدها سرّ، ولا يُكتب منها
> حرف واحد في Git ولا يُلصق في محادثة.

**علامة البيئة** — سطر واحد تشغّله على staging **قبل** أي شيء آخر (وليس هجرة، فلا يلمس
مخطّط المنتج):

```sql
create schema if not exists private;
create table if not exists private.environment_marker (env text primary key);
insert into private.environment_marker (env) values ('staging') on conflict do nothing;
```

## 4. حارس البيئة — جاهز ومُثبَت

`scripts/staging/preflight.mjs` · إثباته `npm run test:staging-package` (**٧٠ فحصًا**).

**مرحلتان، والفصل بينهما هو المقصود:**

| المرحلة | تفحص | متى ترفض |
|---|---|---|
| ① **دون اتصال** | منع الإنتاج ← قائمة السماح ← `QIMMAH_TARGET_ENV=staging` | **قبل أي وصول** لقاعدة أو نشر |
| ② باتصال | علامة `private.environment_marker = 'staging'` | بعد نجاح ① فقط |

**ما هو مُثبَت بالتشغيل لا بالادّعاء:**
- مرجع الإنتاج المزروع ⇒ يُرفض `production_ref_denied` **و`connects=0` و`queries=0`** —
  العدّاد هو الإثبات، لا التعليق.
- مرجع فيه كلمة `staging` ⇒ **يُرفض** ما لم يكن مُدرَجًا. الاسم ليس سندًا.
- مرجع الإنتاج مُدرَج في قائمة السماح خطأً ⇒ **المنع يفوز**.
- لا علم `force`/`skip`، ولا استثناء `NODE_ENV`.
- القائمتان تصلانك **فارغتين**، والفراغ يعني الرفض.

## 5. أداة التقاط العقد — جاهزة ومُثبَتة

`scripts/staging/capture-contract.mjs`

تحوّل حمولة **واحدة متحقَّقًا منها** إلى «رصد» صالح للحفظ: **الشكل بلا القيم** (مسار كل
مفتاح ونوعه) + **الحقول الثمانية المسمّاة وحدها** بقيمها.

**مُثبَت أن الرصد لا يحمل:** البريد · الاسم الأول والأخير · الجوال · المدينة · الشارع ·
الرمز البريدي · ملاحظة الطلب · السرّ · التوقيع.
والبريد يُختزل إلى بصمة ١٢ خانة — تكفي لتأكيد «نفس المشتري» ولا تعيد العنوان.

> **غير مكتوب، لا مُنقَّح بعد الكتابة.** الفرق بينهما هو الفرق بين تسريب مؤجَّل وعدمه.

وحمولة بتوقيع فاسد **لا تُلتقط أصلًا**: رصدٌ من مجهول ليس دليلًا على عقد سلة، وقد يكون
مصنوعًا ليضلّلنا عن الشريحة المدفوعة.

## 6. بوّابة قرار الشريحة المدفوعة

**لا تدخل شريحة `SALLA_PAID_STATUS_SLUGS` إلا باجتماع شرطين:**

1. **رُصدت** في حدث سلة رسمي أو تجريبي (رصد مُلتقَط بالأداة أعلاه)، **و**
2. **يثبت الدليل** أنها تمثّل دفعًا **مكتملًا ومستقرًّا** يستحق منح Premium.

**«اسم يبدو نهائيًا» ليس دليلًا.** `completed` قد تعني اكتمال التنفيذ لا اكتمال الدفع؛
والتحويل البنكي قد يصل حالةً «منجزة» قبل تسوية المال.

**الدليل المقبول** (أيّها كفى): توثيق سلة رسمي يصرّح بالدلالة · تأكيد مكتوب من دعم سلة ·
رصد تجريبي يظهر فيه انتقال الحالة **بعد** تأكيد الدفع مع `is_pending_payment = false`.

**عند الغموض: NO-GO.** والقائمة تبقى فارغة، والطرفية لا تقلع — وهو السلوك المقصود.

| الاسم | `salla-webhook` |

مشوَّهة · حدث غير مدعوم · `is_pending_payment = true` · شريحة غير مُدرَجة · منتج غير
مطابق · مبلغ أو عملة مخالفان · تعارض هوية الطلب.

**تسجيل الـwebhook لدى سلة يبقى على نقطة staging وحدها.** لا تسجيل إنتاجي في هذه الحزمة.

## 10. المجهولات الباقية

| المجهول | يُغلق بـ |
|---|---|
| **أي شريحة تعني «وصل المال»** | §6 — رصد + دليل |
| **دلالة `is_pending_payment`** | رصد يظهر فيه `true` قبل الدفع و`false` بعده |
| **استراتيجية الرمز** (`Authorization` أم `X-Salla-Signature`) | تأكيد من سلة — الافتراضي `signature` هو المعتمد ولا حاجة لحسمه إن بقينا عليه |
| **معرّف حدث فريد من سلة** | لا ترويسة موثَّقة؛ نستعيض ببصمة الجسم — كافية للإعادة الحرفية |
| **سلوك الإعادة الفعلي** | رصد محاولتين متتاليتين للتأكّد أن الجسم يتطابق حرفيًا |

## 12. الترتيب التنفيذي — حين تصل المُدخَلات

1. تنشئ مشروع staging → تكتب مرجعه ومرجع الإنتاج في `environment.json`.
2. تشغّل سطر علامة البيئة (§1) على staging.
3. `QIMMAH_TARGET_ENV=staging node scripts/staging/preflight.mjs` ← **لا شيء قبل خضرته**.
4. تضبط الأسرار في لوحة Supabase.
5. تطبَّق الهجرات العشرون بترتيبها، ثم `test:entitlements` + `test:privileges` على staging.
6. تُنشر الطرفية، ويُسجَّل webhook تجريبي على نقطتها.
7. يُلتقط رصدٌ واحد بالأداة (§5) ← تُغلق مجهولات §10.
8. تُملأ `SALLA_PAID_STATUS_SLUGS` و`SALLA_EXPECTED_PRODUCT_IDS` وفق §6 و§7.
9. تُعاد دورة الإثبات كاملة على staging.
10. **عندها فقط** يُعاد النظر في الإنتاج — بأمر مرقّم جديد.

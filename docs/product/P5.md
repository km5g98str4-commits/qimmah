# P5 — تلميع (Polish)

المرحلة الخامسة: تصفير يومي تلقائي، إزالة تكرار يوم التمرين، أوسمة بأسلوب Apple Fitness (SVG)،
وطبقة اتّساق صور التمارين. **Frontend فقط — لا نشر.** كل البوابات خضراء.

| البوابة | النتيجة |
|---|---|
| `npm run build` | ✅ نجح |
| `npm run lint` (max-warnings 0) | ✅ نظيف |
| `npm run typecheck` | ✅ بلا أخطاء |
| `npm run proof:p5reset` | ✅ التصفير التلقائي + حفظ التاريخ |
| `npm run proof:p5plan` | ✅ لا تكرار في الأسبوع المولّد |
| `npm run proof:p5medals` | ✅ لقطة الأوسمة |

## 1) التصفير اليومي التلقائي (Auto day-reset)

**المطلوب:** «إنجاز اليوم» يتصفّر تلقائيًا عند منتصف الليل المحلّي، لا عبر زر يدوي، مع حفظ التاريخ.

**الحالة قبل:** منطق التصفير التلقائي كان موجودًا في `src/lib/today.ts` (`loadToday()` يبدأ صفحة
جديدة عند اختلاف التاريخ المخزّن عن اليوم، إضافةً لمستمع `focus`/`visibilitychange` لو بقيت الصفحة
مفتوحة بعد منتصف الليل) — **لكن** بقي زرّ يدوي «إعادة ضبط اليوم» في `src/sections/Today.tsx`.

**التغيير:**
- أُزيل زرّ «إعادة ضبط اليوم» من `Today.tsx` واستُبدل بسطر تلميح: «يتصفّر تلقائيًا كل يوم عند منتصف
  الليل» (نصّ في `i18n/dict/dashboard.ts` → `autoResetHint`، عربي/إنجليزي).
- التصفير يعتمد ختم اليوم المحلّي `getDayStamp()` (`YYYY-MM-DD`). عند اختلاف المخزّن عن اليوم يُكتب
  «اليوم» صفحةً جديدة، بينما تبقى لقطة الأمس في المتجر التاريخي الدائم (`historyStore` →
  `dailyLogs`) لأنها تُحفظ تدريجيًا مع كل علامة (`saveDailyLog`).

**الإثبات (`proof:p5reset`)** — يحاكي إغلاق التطبيق أمس ثم فتحه اليوم فوق `localStorage` مُحاكى:

```
اليوم=2026-07-01  الأمس=2026-06-30
✅ سجلّ الأمس محفوظ في المتجر التاريخي قبل التصفير
✅ «اليوم» تصفّر تلقائيًا لتاريخ اليوم (2026-07-01)
✅ علامات اليوم فارغة بعد التصفير التلقائي
✅ سجلّ الأمس ما زال كاملًا بعد التصفير (لا فقدان تاريخ)
✅ مفتاح التخزين يحمل تاريخ اليوم الجديد
```

## 2) إزالة تكرار يوم التمرين (Dedupe workout day)

**المطلوب:** يوم «دفع» (الأربعاء) يظهر خيارين/مكرّرين — كل يوم تدريب يجب أن يعرض تمرينًا واحدًا واضحًا.

**التشخيص (بالتشغيل الفعلي للمولّد):** مولّد الخطة `src/lib/planGenerator.ts` **لا يُنتج أيامًا
مكرّرة** — كل يوم يُسمّى «اليوم N · …» فيبقى فريدًا، وكل يوم أسبوع يُميَّز باسمه. أثبت ذلك
`proof:p5plan` لكل الأعداد (3/4/5/6/7 أيام):

```
— 6 أيام — تقسيمة: gen-ppl-6
  أيام الخطة: اليوم 1 · دفع | اليوم 2 · سحب | اليوم 3 · أرجل | اليوم 4 · دفع | اليوم 5 · سحب | اليوم 6 · أرجل
✅ لا تكرار في أسماء أيام الخطة (6 أيام)
```

المصدر الحقيقي لـ«الأربعاء دفع مكرّر» كان **بيانات المعاينة الثابتة** `src/data/routine.ts`: أسبوع
بستّة أيام تدريب مضغوطة في خمسة أنواع فقط، فتكرّر «دفع» (السبت + الأربعاء) وقُرئ كتكرار مربك.

**التغيير:** أُعيد تصميم الأسبوع التجريبي في `routine.ts` إلى خمسة أيام تدريب بأنواع **متمايزة بلا
تكرار** (دفع / سحب / أرجل / علوي / كارديو) + راحة — كل يوم تمرين واحد واضح، ولا بطاقتَي «دفع».

**الإثبات:** `proof:p5plan` يؤكد خُلوّ الأسبوع المولّد من التكرار لكل الأعداد، ويؤكد أن
`todayPlanDay` يغطّي كل أيام الخطة دون ازدواج.

## 3) أوسمة بأسلوب Apple Fitness (SVG)

**المطلوب:** استبدال إيموجي الأوسمة بأوسمة SVG مصمّمة (حلقات معدنية متدرّجة، لون مميّز لكل فئة،
مقفلة رمادية ومفتوحة بلون كامل ولمعان)، بثبات الحجم/الشكل عبر الـ19، وبلا إيموجي، مع إبقاء منطق
الفتح كما هو.

**التغيير:**
- **`src/lib/medalArt.ts`** — مولّد قرص الوسام كسلسلة SVG (حلقة معدنية متدرّجة + حزّات + وجه إشعاعي
  + لمعان علوي + توهّج للمفتوح). لوحة ألوان لكل فئة:
  - سلاسل (`streak`) = **برتقالي** · بروتين (`protein`) = **أخضر** · خطوات (`steps`) = **أزرق** ·
    قوّة/أرقام (`strength`) = **ذهبي** · بدايات/معالم (`firsts`) = **بنفسجي**.
  - المقفل = رمادي مُطفأ بلا توهّج + شارة قفل.
- **`src/components/MedalBadge.tsx`** — يركّب القرص (SVG ثابت مُولّد داخليًا) + أيقونة lucide مركزية
  حادّة (لكل وسام أيقونته من `src/lib/icons.ts`)، بحجم قابل للضبط وثابت الأسلوب.
- **`src/data/achievements.ts`** — استُبدل حقل `emoji` بحقل `icon` (اسم أيقونة lucide) لكل الـ19.
  **منطق الفتح لم يُمسّ** (العتبات/المقاييس/الفئات كما هي).
- استُبدلت كل الإيموجي في البطاقة (`AchievementsCard`) والاحتفال (`AchievementToaster`) بـ
  `MedalBadge`/أيقونات. لا إيموجي في مسار الأوسمة إطلاقًا.

**اللقطة:** `docs/product/assets/p5-medals.png` (تُولَّد بـ `proof:p5medals` عبر Chromium headless
باستخدام **نفس** قرص `medalArt` وأيقونات lucide المستخدمة في التطبيق — تطابق بصري مضمون).

**التقييم البصري (نُظر إلى اللقطة):** الـ19 وسامًا في العمودين (مفتوحة/مقفلة) بحجم وشكل وأسلوب
موحّد؛ الأقراص معدنية بلمعان وتوهّج للمفتوح، ورمادية مُطفأة مع قفل للمقفل؛ الألوان مميّزة لكل فئة؛
الأيقونات حادّة (تكبير بلا تحبّب)؛ **بلا إيموجي**. المظهر متّسق وفاخر.

## 4) اتّساق صور التمارين (Image consistency)

**المطلوب:** تمرير اتّساق — مصدر/أسلوب موحّد قدر الإمكان، حجم/نسبة/خلفية موحّدة، بديل موحّد للـ34 غير
المطابَق، وتوثيق صادق أن العروض المتحرّكة الموحّدة تمامًا تتطلّب `WORKOUTX_API_KEY`.

**الحالة (طبقة الاتّساق قائمة وصلبة):**
- **مصدر واحد:** كل الصور من قاعدة عامة واحدة `yuhonas/free-exercise-db` (Unlicense) — أسلوب موحّد
  لكل تمرين. **التغطية: 136/170 تمرينًا** (34 غير مطابَق — أساسًا الكارديو ومفردات نادرة).
- **حجم/نسبة/خلفية موحّدة:** `ExerciseMedia` يعرض بـ `object-cover` داخل إطار بارتفاع ثابت وخلفية
  تدرّج داكن موحّد (قصّ/تأطير متطابق). الصور المصغّرة في المكتبة (`ExerciseThumb`) بإطار `h-12 w-12`
  موحّد بنفس الخلفية.
- **بديل موحّد للـ34:** `ExercisePlaceholder` (وبديل المصغّرة) — نفس الإطار والتدرّج وأيقونة الدمبل،
  فلا صورة مكسورة أبدًا وتبقى الشبكة متّسقة بصريًا بين المطابَق وغير المطابَق.

**المنفذ (seam) للعروض المتحرّكة — موثّق بصدق:**
- سكربت البناء `scripts/build-exercise-media.mjs` جاهز لمنفذ `WORKOUTX_API_KEY`: بلا مفتاح نعرض أفضل
  الإطارات الثابتة المتّسقة (إطار بداية/نهاية بتلاشٍ متبادل لمحاكاة الحركة)؛ ومع المفتاح تُجلب عروض
  GIF متحرّكة موحّدة الأسلوب (Strong-style) وتُفضّل تلقائيًا (`gifUrl`).
- المفتاح **ليس** `VITE_*` — يُستخدم فقط وقت البناء على Node ولا يُحقن في حزمة المتصفّح. أُضيف موثّقًا
  بقيمة فارغة في `.env.example`.
- **لم تُفبرَك أي GIF متحرّكة.** بدون المفتاح نلتزم بالإطارات الثابتة الأكثر اتّساقًا فقط.

## المخاطر والملاحظات

- **`routine.ts` بيانات معاينة ثابتة** (تسويقية) لا مولّدة؛ تعديلها لا يمسّ منطق المولّد. المولّد نفسه
  مُثبَت خُلوّه من التكرار عبر `proof:p5plan`.
- **`todayPlanDay`** يختار يوم الخطة عبر `getDay() % عدد الأيام` (مستقلّ عن جدول الأسبوع). أُبقي كما هو
  (خارج نطاق «التكرار»)؛ لا يُنتج ازدواجًا لكنّه قد لا يطابق ترتيب أيام الجدول تمامًا — تحسين مستقبلي.
- **حقن SVG:** `MedalBadge` يستخدم `dangerouslySetInnerHTML` لقرص SVG **ثابت مُولّد داخليًا بلا أي
  مدخل مستخدم** — آمن ضمن قاعدة الأمان (محتوى موثوق ومعقّم).
- **صور التمارين المتحرّكة تمامًا** تتطلّب `WORKOUTX_API_KEY` (مجّاني)؛ المنفذ جاهز دون أي مفتاح في
  المستودع.
- **لا نشر** في هذه المرحلة (بطلب صريح لمعاينة لقطة الأوسمة أولًا).

# P10 · A1 — باني الجدول المخصّص (Custom Workout Plan Builder)

> المستخدمون طلبوا بناء جدولهم بأنفسهم: اختيار التمارين، عدد الأيام، تقسيمها،
> وإعادة ترتيبها بحرية — كخيار واضح بعد التسجيل بجانب الجدول المولّد تلقائيًا.

## ما الذي أُضيف

ميزة قائمة بذاتها في `src/features/customPlan/**` + نقطتا دخول (الإعداد + تبويب التمرين)
+ توصيل «مصدر الجدول» في عرض التمرين. **لم تُمَس** حسابات التغذية، منطق المصادقة،
ملفات بيانات التمارين، أو قواميس i18n العامة (الميزة تحمل قاموسها الخاص).

### الملفات الجديدة (`src/features/customPlan/`)
| ملف | الدور |
|---|---|
| `strings.ts` | كل نصوص الميزة (عربي خليجي + إنجليزي)، RTL. |
| `storage.ts` | تخزين لكل حساب + اختيار المصدر (تلقائي/مخصّص). |
| `defaults.ts` | أسماء أيام مقترحة حسب العدد + عمليات بناء/تعديل `WorkoutPlan`. |
| `ExercisePickerSheet.tsx` | منتقي تمارين: بحث + فلتر عضلة + صورة/GIF مصغّرة + نقر للإضافة. |
| `CustomPlanBuilder.tsx` | الباني: أيام → بناء (اسم/تمارين/ترتيب/مجموعات×تكرار) → مراجعة → حفظ. |
| `PlanChoiceScreen.tsx` | شاشة اختيار «جاهز» مقابل «أصمّم بنفسي» في الإعداد. |
| `index.ts` | تصدير الميزة. |

### الملفات المعدّلة (ضمن نطاق الملكية)
- `src/components/PlanBuilder.tsx` — شاشة الاختيار بعد الأساسيات + فتح الباني عند اختيار «مخصّص».
- `src/views/WorkoutView.tsx` — قراءة الجدول الفعّال + مبدّل المصدر + دخول إنشاء/تعديل + تشغيل الباني.

## شاشات التدفّق (الإعداد)
`الاسم → الهدف → الجنس → العمر → الطول → الوزن → **طريقة الجدول** → … → توليد → الباني المخصّص`

شاشة **طريقة الجدول** بطاقتان بارزتان: «جدول جاهز حسب هدفك» (الافتراضي، مع شارة «موصى به»)
و«أصمّم جدولي بنفسي». عند اختيار «مخصّص» يُكمل المستخدم بقية الإعداد (لأجل التغذية والأهداف
وجدول تلقائي كأساس/بديل)، ثم بعد شاشة التوليد يُفتح الباني ليصمّم جدوله من الصفر.

خطوات الباني:
1. **الأيام** — عدّاد 2–6، مع أسماء أيام مقترحة لكل عدد (دفع/سحب/أرجل…).
2. **البناء** — تبويبات أيام؛ لكل يوم: اسم قابل للتعديل، إضافة تمارين من المكتبة الكاملة
   (بحث + فلتر عضلة + صورة مصغّرة)، ترتيب بأزرار ↑/↓ (أهداف لمس ≥40px)، وضبط مجموعات×تكرار
   بقيم افتراضية من المكتبة قابلة للتعديل، وحذف.
3. **المراجعة** — ملخّص كل يوم وتمارينه + الإجمالي، ثم **حفظ**.

## الاستمرار (لكل حساب)
- المفتاح `qimmah:customPlan:v1` = سجلّ `{ [userId | 'guest']: { plan, source, updatedAt } }`،
  على نمط `qimmah:onboarding:accounts:v1` (سجلّ مفتاحه معرّف الحساب) الذي أرساه إصلاح
  «الإعداد لكل حساب». حساب جديد لا يرث جدول حساب آخر؛ الضيف تحت مفتاح `guest`.
- الجدول من نوع `WorkoutPlan` القائم، فيعمل مباشرةً في العرض ووضع التمرين بلا تحويل.

## نقاط الدخول
1. **الإعداد/بعد التسجيل**: شاشة الاختيار بعد الأساسيات (`PlanBuilder`).
2. **تبويب التمرين**: زر «إنشاء جدول مخصّص» (عند عدم وجوده) أو «تعديل جدولي» (عند وجوده)،
   ومبدّل «الجدول التلقائي / جدولي المخصّص» للتبديل في أي وقت.

## توصيل وضع التمرين
`WorkoutView` يقرأ الجدول الفعّال عبر مصدر الحساب: مخصّص إن اعتُمد وفيه أيام، وإلا التلقائي.
بطاقات الأيام، قائمة التمارين بالوسائط، وتسجيل الجولات تعمل كما هي — الجدول التلقائي يبقى
الافتراضي لمن لم يخصّص.

## اللغة والهوية
كل النصوص عربي خليجي + إنجليزي (مفاتيح جديدة في قاموس الميزة). RTL صحيح، هوية داكنة/برتقالية/Tajawal
باستخدام أصناف النظام (`.card` `.btn-primary` `ink` `line` `surface` `primary`).

## الإثبات (متصفّح بلا رأس)
`node scripts/p10-a1-proof.mjs` (بعد `npm run build`) — يقود التطبيق الحقيقي:
اختيار «مخصّص» في الإعداد → بناء جدول 3 أيام (أيام → إضافة تمارين ببحث/فلتر → ترتيب → تكرار → حفظ)
→ تبويب التمرين يعرضه → تحديث الصفحة يُبقيه → وضع التمرين يشغّله → التبديل للتلقائي والعودة.
اللقطات في `docs/product/p10-a1/`.

نتيجة التشغيل:


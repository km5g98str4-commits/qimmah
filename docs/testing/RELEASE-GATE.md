# بوابة الإصدار — `npm run test:release-gate`

نقطة تشغيل واحدة قبل أي إطلاق. تجمع ثلاث طبقات كانت متفرّقة في أوامر منفصلة،
وتُخرج تقريرًا زمنيًا لكل مرحلة في `docs/testing/release-gate-latest.json`.

## ماذا تُشغّل

| الطبقة | المراحل |
|---|---|
| **أساس** | `typecheck` · `lint` · `build` |
| **إثباتات** | `test:gate` — ٤٥ سكربت إثبات وحدوي |
| **متصفّح حيّ** | `e2e: onboarding` · `e2e: journey` · `e2e: settings-security` |

## الأوضاع

```bash
npm run test:release-gate
```
```bash
npm run test:release-gate -- --fast
```
```bash
npm run test:release-gate -- --bail
```

`--fast` يتخطّى طبقة المتصفّح (للتكرار السريع أثناء التطوير)، و`--bail` يتوقّف
عند أوّل فشل. الافتراضي: يُكمل كل المراحل ليعطي صورة كاملة عن حالة الإصدار.

## لماذا سكربت بدل سلسلة `&&`

- سلسلة `&&` تتوقّف عند أوّل فشل فلا تعرف ما الذي كان سيمرّ؛ هنا تُعرض كل المراحل.
- قياس زمن كل مرحلة — الزمن أوّل ما يتدهور في بوابة تكبر مع الوقت.
- البناء يُنفَّذ **مرّة واحدة**؛ الأوامر الثلاثة القديمة (`test:e2e`، `test:e2e:journey`،
  `test:e2e:settings-security`) كان كلٌّ منها يبدأ بـ `npm run build` من جديد.
- تقرير JSON قابل للقراءة آليًا (لـ CI أو لوحة متابعة).

## النصوص والمفاتيح: مصدر حقيقة واحد

كانت سكربتات E2E تكرّر نصوص الواجهة العربية ومفاتيح التخزين حرفيًا، فأي تعديل
على النصّ في المصدر يكسر الاختبار بخطأ مضلّل — يبدو عطلًا في المنتج وهو مجرّد
نصّ تغيّر. الآن كلّها تمرّ عبر `scripts/e2e/lib/app-copy.mjs`:

| المصدر | ماذا يوفّر |
|---|---|
| `src/design-system/v2/labels.ts` | نصوص الإعداد (`V2_ONBOARDING`) ونموذج الأهداف |
| `src/data/policyCopy.ts` | نصّ إقرار البيانات الصحية |
| `src/lib/userDataKeys.ts` | سجلّ مفاتيح التخزين (`DATA_KEYS` — ٦١ مفتاحًا) |

ثلاث دوال حراسة تجعل الانحراف يسقط بصوت عالٍ بدل أن يمرّ صامتًا:

- `requireKey()` — يرمي إن اختفى مفتاح من السجلّ (الاختبار يفحص شيئًا لم يعد موجودًا).
- `assertUnregistered()` — يرمي إن **سُجِّل** مفتاح حالة «متجر مجهول»، فتفقد الحالة معناها.
- `assertDevFlag()` — أعلام التطوير ليست مفاتيح بيانات ولا ثوابت مُصدَّرة، فنتحقّق
  أنها ما زالت مقروءة في ملفّها المصدري.

**الحراسة أثبتت نفسها فورًا:** `requireKey('qimmah:custom-plan:v1')` سقط في أول
تشغيل — تبيّن أن المفتاح غير مسجّل **عمدًا** لأنه حمولة هجوم تمثّل متجرًا مجهولًا،
فصُحّح التأكيد إلى `assertUnregistered` الذي يوثّق النيّة بدقّة.

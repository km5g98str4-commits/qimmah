# Qimmah — Food Database Strategy (v2 Foundation)

> الهدف: قاعدة بيانات أطعمة **قانونية، قابلة للتوسّع، ومركّزة على المستخدم السعودي/الخليجي**.
> الحالة: أساس (foundation) مُنفّذ في `src/data/foodDatabase.ts` + `src/lib/foodSearch.ts` + نوع `FoodV2` في `src/types/nutrition.ts`.
> التاريخ: 2026-06-28 · الفرع: `feature/v2-food-database-foundation`

---

## 1. لماذا لا نسحب بيانات MyFitnessPal / Marn؟ (الحدّ القانوني)

**ممنوع منعًا باتًا**، ولم نفعل أيًّا منه في هذا العمل:

- **لا scraping / crawling** لأي تطبيق أو موقع مغلق (MyFitnessPal, Marn, أو غيرها).
- **لا APIs غير رسمية** أو هندسة عكسية لنقاط نهاية خاصة.
- **لا نسخ مجموعات بيانات ضخمة** من تطبيقات مملوكة.

**الأسباب:**
1. **حقوق الملكية وقواعد البيانات:** محتوى هذه التطبيقات محمي بشروط الخدمة وحقوق قاعدة البيانات؛ نسخه أو إعادة توزيعه خرق قانوني وتعاقدي.
2. **شروط الاستخدام (ToS):** تمنع صراحةً الاستخراج الآلي وإعادة الاستخدام التجاري.
3. **مخاطر تجارية:** قِمّة منتج **تجاري قابل للبيع**؛ أي بيانات منسوخة بطريقة غير قانونية تُحوّل المنتج إلى مسؤولية قانونية وتمنع بيعه.
4. **الجودة والثقة:** القيم المسحوبة بلا ترخيص لا يمكن التحقق من مصدرها أو تحديثها أو الدفاع عنها.

> القاعدة الذهبية: **إن لم نملك حق استخدام البيان، لا يدخل القاعدة.**

## 2. استراتيجية البيانات القانونية (مصادر مسموحة فقط)

نوع `FoodV2.source` يفرض شفافية المصدر لكل صنف:

| `source` | الوصف | الاستخدام الحالي |
|---|---|---|
| `qimmah_curated` | قيم **منسوخة يدويًا** من معرفة غذائية عامة (تقديرية، غير محمية كتعبير) | كل الأصناف الـ101 الحالية |
| `open_dataset` | مجموعات بيانات **مفتوحة الرخصة** (Public Domain / CC0 / ODbL مع الإسناد) | محجوز للمستقبل (لا يوجد ملف حاليًا) |
| `user_custom` | أطعمة يُدخلها المستخدم بنفسه ويملك حقها | عبر «الإضافة السريعة» الحالية |

كل صنف يحمل أيضًا `confidence` (`high`/`medium`/`low`) — **لا ادّعاء دقة طبية**؛ القيم تقديرية وتظهر مع تنويه `FOOD_ESTIMATE_NOTE`.

### الحقائق ليست محمية، التعبير محمي
القيمة الغذائية لـ«100غ رز أبيض = ~130 سعرة» **حقيقة عامة** غير قابلة للاحتكار. ما يُحظر هو **نسخ تجميع/تنظيم/تعبير** جهة معيّنة. لذلك نحن نعيد بناء القيم من معرفة عامة ونصوغ الأسماء/الحصص بأنفسنا.

## 3. خيارات البيانات المفتوحة (للمستقبل)

عند الحاجة للتوسّع بمصادر خارجية، نقتصر على **مفتوحة الرخصة وقابلة للإسناد**:

- **USDA FoodData Central** — Public Domain (U.S. Gov). مرجع ممتاز للأطعمة المفردة (لحوم، حبوب، خضار).
- **Open Food Facts** — رخصة ODbL (قاعدة) + DbCL (المحتوى). مناسبة للمنتجات المعبّأة والباركود، مع **وجوب الإسناد** والحفاظ على الرخصة المفتوحة لأي مشتق.
- **FRIDA (DTU, Denmark)** وقواعد حكومية مشابهة — تتطلب مراجعة رخصة كل منها.

> ⚠️ تنبيه ODbL: إن استوردنا Open Food Facts، فالحقول المشتقة قد تخضع لشرط share-alike. يجب فصلها بوضوح (`source: 'open_dataset'`) ومراجعة قانونية قبل الدمج في منتج تجاري.

## 4. قاعدة قِمّة المنسوخة يدويًا (الأساس الحالي)

- **101 صنف** في `src/data/foodDatabase.ts`، مصدرها `qimmah_curated`.
- تركيز سعودي/خليجي: كبسة/مندي/بخاري/برياني/مظبي/مدفون/سليق، تميس/مطبق/خبز تنور، معصوب/عريكة/فول، كرك/قهوة عربية، كنافة/بسبوسة/لقيمات.
- **كل صنف يُظهر:** وسم حصة عربي/إنجليزي + الغرامات (متى عُرفت) + سعرات وماكروز لكل حصة + `per100g` **مشتق آليًا** من الغرامات (يمنع أخطاء الحساب اليدوي).
- الفئات إنجليزية ثابتة (`rice/meat/chicken/...`) لتسهيل الفلترة، مع `cuisine` (`saudi/gulf/levant/egyptian/international`) لترتيب الأولوية.

### التوافق مع النظام الحالي (عدم الكسر)
- `foodItems.ts` القديم **لم يُمسّ**؛ `QuickMealLogger` و`NutritionView` يعملان كما هما.
- جسر `foodV2ToLegacy()` في `foodDatabase.ts` يحوّل `FoodV2 → FoodItem` (مع خريطة فئات عربية)، فيمكن **دمج قاعدة v2 في البحث الحالي مستقبلًا** بسطر واحد دون تغيير المكوّنات:
  ```ts
  // مثال دمج مستقبلي داخل QuickMealLogger (غير مفعّل الآن):
  // import { foodDatabase, foodV2ToLegacy } from '@/data/foodDatabase'
  // const v2Legacy = foodDatabase.map(foodV2ToLegacy)
  // ثم دمجها مع foodItems مع إزالة التكرار بالاسم المطبّع.
  ```
- خطة الدمج الموصى بها: توحيد المصدر تدريجيًا على v2، وإزالة التكرار **بالاسم المطبّع** مع تفضيل `confidence` الأعلى، بدل حذف أي صنف قديم فورًا.

## 5. كيف يضيف المستخدم أطعمته الخاصة؟

- موجود اليوم: تبويب **«إضافة سريعة»** في `QuickMealLogger` (سعرات/بروتين/كارب/دهون يدويًا) → يُسجّل كـ`user_custom` منطقيًا.
- المسار المستقبلي: حفظ الأطعمة المخصّصة في `localStorage` (نفس نمط المتجر المحلي) بنوع `FoodV2` و`source: 'user_custom'`، مع ظهورها في البحث جنبًا إلى جنب القاعدة المنسوخة.
- المستخدم يملك حق بياناته الخاصة → لا قيود قانونية على إدخالها أو تصديرها.

---

## 6. المستقبل: الباركود وقواعد المنتجات المفتوحة

- **مسح الباركود (Barcode):** الربط بـ **Open Food Facts** (ODbL) لجلب المنتجات المعبّأة عبر EAN/UPC — مع الإسناد والالتزام بالرخصة.
- تخزين `brand_ar/brand_en` (موجود في schema) لدعم المنتجات ذات العلامة التجارية.
- التخزين المؤقت (cache) محليًا لتقليل الطلبات، مع تحديث دوري.

---

## 7. المستقبل: أطعمة من المستخدمين مع إشراف (moderation)

- السماح للمستخدمين باقتراح أطعمة عامة (لا خاصة) لإثراء القاعدة المشتركة.
- **طبقة إشراف**: مراجعة بشرية + حدود قيم منطقية (مثل: سعرات/غرام ضمن نطاق معقول) قبل الاعتماد.
- وسم `source: 'user_custom'` و`confidence: 'low'` حتى التحقق، ثم ترقيتها.
- حماية من التلوّث: لا دمج تلقائي في القاعدة الأساسية بلا مراجعة.

---

## 8. الخلاصة

أساس قانوني نظيف: **مصدر واضح لكل صنف، ثقة صريحة، تطبيع بحث ذكي بالعربية واللهجة، توافق تام مع الواجهة الحالية، وطريق توسّع** (مفتوح/باركود/مستخدمين) لا يعتمد على أي بيان مسروق.

`.food-cache/` غائب اليوم، فالبداية تنزيلٌ حجمه **١٫٢ غيغابايت**.

SOURCE_DATE_EPOCH=1786000000 npm run food:ingest
npm run food:build

**التحقّق مجّاني ومضمون:** بصمات `sha256` و`index_sha256` للشرائح الـ٤١ **ملتزمة أصلًا** في

⚠️ **`npm run food:emit` لا ينسخ الشرائح — عمدًا** (`scripts/food-production/emit-static-assets.mjs:2-6`).

## ٣. الخيار (أ) — تحت `public/food/shards/` وتركب في `dist/` ← **التوصية**

### هل يجوز أصلًا؟ نعم، والحدود مقيسة لا مفترضة

| حدّ Cloudflare Pages | القيمة | حالنا | الهامش |
|---|---|---|---|
| أقصى حجم ملف واحد | **25 MiB** | 1.82 م.ب (أكبر شريحة) | **×13.7** |
| أقصى عدد ملفات (خطة مجانية) | **20,000** | 294 → **376** ملفًا | **×53** |
| أقصى عدد ملفات (خطة مدفوعة) | 100,000 | — | — |

> المصدر: `developers.cloudflare.com/pages/platform/limits/` — «The maximum file size for a
> single Cloudflare Pages site asset is 25 MiB» و«up to 20,000 files on the Free plan».

**و`public/food/shards/` غير مُتجاهَل في git** — تحقُّقٌ منفَّذ:
`git check-ignore public/food/shards/shard-00.json` ⇒ خروج 1 (غير متجاهَل).
فلا يحتاج الخيار تعديل `.gitignore` إطلاقًا.

### الخطوات

```bash
# بعد §٢:
mkdir -p public/food/shards
cp data/food-production/accepted/shards/*.json public/food/shards/
node scripts/run-food-longtail-proof.mjs   # يجب أن يقول: ٤١/٤١ حاضرة · الحكم «available»
npm run build                              # Vite ينسخ public/ حرفيًا إلى dist/
```

ثم الالتزام والدفع إلى `main` — و**هذا هو فعل النشر** الذي يحتاج تفويض المؤسس.

### الكلفة الحقيقية، بلا تجميل

- **المستودع يكبر ~81.4 م.ب خامًا** (git يضغطها إلى ~15.5 م.ب لكل نسخة). وكل إعادة توليد
  لاحقة تضيف ~15.5 م.ب أخرى، لأن git لا يحذف التاريخ.
- **يعكس قرارًا موثَّقًا**: `public/food/README.md` و`emit-static-assets.mjs` يقولان صراحةً إن
  الشرائح «تُرفع للاستضافة الساكنة عند النشر» ولا تُلتزم. **قلبُ هذا قرار مؤسس معلَن،
  لا تفصيلة تنفيذ** — ويُحدَّث النصّان معه، وإلا صارت الوثيقة تكذب على قارئها.

### لماذا هي التوصية رغم ذلك

**لا أصل جديد، ولا سياسة محتوى تُمسّ، ولا خدمة تُفعَّل.** الشرائح تُخدَم من نفس المصدر
(`/food/...`)، فـ`connect-src 'self'` يغطّيها كما هي، ولا CORS ولا نطاق ولا مفاتيح. وهي
**أصغر معمارية صحيحة** بالمعنى الحرفي: عدد القطع المتحرّكة صفر فوق ما هو قائم.

**لا يُوصى به** إلا مع تخزين مؤقّت لـ`.food-cache/` في CI، وهو تعقيد لا يقابله عائد اليوم.

## ٥. الخيار (ج) — دلو R2 بنطاق مخصّص

### ⛔ عائق مقيس أولًا: **R2 غير مفعَّل على هذا الحساب**

نداء `r2_buckets_list` عاد:

```
403 {"success":false,"errors":[{"code":10042,
     "message":"Please enable R2 through the Cloudflare Dashboard."}]}
```

فأي خطوة R2 تبدأ بتفعيل الخدمة من لوحة Cloudflare — **فعلٌ يخصّ المؤسس**، ولا يمكن لأي وكيل
تجاوزه بأداة.

### الخطوات، بعد التفعيل

1. **إنشاء الدلو** — لوحة Cloudflare ← R2 ← Create bucket، اسمًا مثل `qimmah-food`.
2. **الرفع.** `wrangler r2 object put` يرفع **كائنًا واحدًا في كل نداء** (والحدّ 315 م.ب/ملف)،
   فرفع ٨٢ ملفًا يمرّ بـ`rclone` أو أي عميل متوافق مع S3:
   ```bash
   rclone copy data/food-production/accepted/shards r2:qimmah-food/food/shards \
     --header-upload "Content-Type: application/json" \
     --header-upload "Cache-Control: public, max-age=31536000, immutable"
   rclone ls r2:qimmah-food   # تحقّق: ٨٢ كائنًا
   ```
   *(`Cache-Control` طويل آمن هنا لأن اسم الملف يحمل رقم الشريحة وبصمتها في البيان؛ أي
   إعادة بناء تغيّر البصمة فيكشفها البيان.)*
3. **نطاق مخصّص** — R2 ← الدلو ← Settings ← Custom Domains ← Add، مثلًا `food.qimmah.app`.
   النطاق يجب أن يكون **zone في نفس الحساب**. لا يُستعمل `*.r2.dev` في الإنتاج: موثَّق أنه
   محدود المعدّل ومخصّص للتطوير.
4. **CORS على الدلو** — يسمح بأصل التطبيق:
   ```json
   [{ "AllowedOrigins": ["https://qimmah-8qp.pages.dev"],
      "AllowedMethods": ["GET"], "AllowedHeaders": ["*"], "MaxAgeSeconds": 86400 }]
   ```
5. **توجيه التطبيق** — بلا تعديل كود:
   ```
   VITE_FOOD_CDN_BASE=https://food.qimmah.app/food
   ```
   يقرأها `src/lib/food/catalog/appCatalog.ts` وتُمرَّر إلى `Catalog.create({ baseUrl })`.
   غيابها يُبقي `/food` كما هو اليوم.

### ⚠️ الخطوة التي تُنسى فتُسقط الميزة صامتةً

`public/_headers` يحمل اليوم:

```
connect-src 'self' https://*.supabase.co wss://*.supabase.co https://world.openfoodfacts.org
```

**لا أصل R2 فيه.** بلا إضافته يحجب المتصفّح كل طلب شريحة، ويعود `fetchText` بـ`null` —
فتبدو الميزة «تعمل وتتدهور بأدب» بينما هي **محجوبة بسياستنا نحن**. الإضافة المطلوبة:

```
connect-src 'self' https://*.supabase.co wss://*.supabase.co https://world.openfoodfacts.org https://food.qimmah.app
```

`public/_headers` **خارج ملفات هذه الحارة** — يُنفَّذ عبر مالكه.

## ٦. الخلاصة والتوصية

| | (أ) `public/food/shards/` | (ب) توليد في CI | (ج) R2 + نطاق |
|---|---|---|---|
| بنية جديدة | **لا شيء** | تخزين CI مؤقّت | تفعيل R2 · دلو · نطاق · CORS |
| تعديل CSP | **لا** | لا | **نعم** (وإلا حُجبت صامتة) |
| كلفة كل نشرة | صفر | ١٫٢ غ.ب تنزيلًا | صفر |
| كلفة المستودع | **+~15.5 م.ب لكل نسخة** | صفر | صفر |
| عوائق اليوم | يعكس قرارًا موثّقًا | هشاشة طرف ثالث | **R2 غير مفعَّل (403)** |

> **التوصية: (أ) الآن، و(ج) حين يتكرّر تحديث الكتالوج.**

> على حدود Pages ×13.7 في الحجم و×53 في العدد. وكلفتها الوحيدة وزن المستودع — وهي كلفة
> تُدفع مرّة، وتُراجَع حين تصير إعادة التوليد دوريّة فينتقل الثقل إلى R2.

## ٧. ما لا يغيّره أي رفع — وهذا هو الجزء المهمّ للمنتج

الذيل الطويل **قاعدة باركود**: 59,583 من 59,941 سجلًا **بلا اسم عربي**
(`build-summary.json` · `FOOD-PRODUCTION-REPORT.md` §٧). فرفع الشرائح كاملةً:

- ✅ **يعطي** حلّ باركود دون اتصال لستين ألف منتج معبّأ بدل ٥٩٩.
- ❌ **لا يعطي** ولا نتيجة إضافية لـ«شاورما» أو «كبسة» أو «مندي» — لأنها **وجبات مركّبة**
  لا سلعًا مغلّفة.

**عمق البحث العربي عن الوجبات تخدمه `src/data/foodItems.ts` (٦٤١ صنفًا)، وقد وُصل في
`[SOVEREIGN-FOOD-001]`** — وهو الذي نقل «شاورما» من ٠ إلى ١٢ و«كبسة» من ٠ إلى ١٢. فمن قرأ
«٥٠ ألف صنف» على أنها عمقُ بحثٍ عربي، **لا يسلّمه الرفعُ ذلك ولو تمّ بالكامل**.

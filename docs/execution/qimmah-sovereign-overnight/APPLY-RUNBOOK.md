
## ٣. زرع الملح — **بدونه يفشل كل نداء كتابة**

كل دوال الوصول تُبصم الهوية بملح مُرقَّم. قاعدة بلا ملح ⇒ كل RPC كتابة يفشل.
تُنفَّذ **مرّة واحدة** من محرّر SQL في لوحة Supabase (لا من هذا المستودع، ولا
من أي ملفّ يُودَع):

```sql
insert into private.identity_pepper (version, pepper)
values (1, '<قيمة عشوائية ٣٢ بايتًا على الأقلّ>')
on conflict (version) do nothing;
```

> **لا تُودَع هذه القيمة في Git ولا تُرسَل في رسالة.** ولا تُغيَّر بعد أول كتابة:
> تغييرها يُبطل كل سطر في السجلّات الدائمة.

## ٤. منح دور المؤسس

```sql
select public.admin_set_role('<بريد المؤسس>', 'founder', 'OVERNIGHT initial provisioning');
```
ثم **سجّل خروجًا ودخولًا**: `app_metadata` يدخل الـJWT لحظة إصداره، وقبل ذلك
تقول الشاشة `denied-by-server` — وهي محقّة.

**التراجع:** `select public.admin_clear_role('<البريد>', '<السبب>');` — لا يمسّ بيانات.

## ٥. ما يحتاج فعلًا خارج قاعدة البيانات

| البند | الحالة | ما يلزم |
|---|---|---|
| مزوّد بريد | `EMAIL_PROVIDER_EXTERNAL` | حساب + مفتاح، ثم `EMAIL_PROVIDER_KIND` |
| سجلّات SPF/DKIM/DMARC | مفقودة | إعداد DNS لنطاق الإرسال |
| سرّ webhook سلة | مفقود | `SALLA_WEBHOOK_SECRET` من لوحة سلة |
| ربط معرّف المنتج | مفقود | `SALLA_EXPECTED_PRODUCT_IDS` = `1181109938` |
| نشر دوال الحافة | لم يُنشر | `supabase functions deploy salla-webhook` و`qimmah-mailer` |
| **تحديد المعدّل** | **غير موجود** | قاعدة Cloudflare أو حدّ بوّابة أمام Supabase — **إلزامي قبل الإطلاق التجاري** |
| تصريف الصادر | غير مجدول | `pg_cron` + `pg_net` |

## ٦. تناقض تجاري يسبق كل ما سبق

صفحة الشروط في المتجر الحيّ تقول حرفيًّا: «اشتراك قمة سنوي … **وينتهي بعد سنة
ميلادية كاملة**»، والخلفية تكتب `no_expiry = true` (شراء واحد بلا انتهاء).
**هذا تناقض بين ما نبيعه وما نمنحه، على السطح القانوني المُلزِم.**
لم يُمَسّ: تعديل نصّ متجر حيّ فعلٌ إنتاجيّ محجوز للمؤسس.
**يُحسم قبل أي إطلاق مدفوع.**
